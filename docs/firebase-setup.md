# Firebase Google login

In Firebase Console, open Authentication and enable the Google sign-in provider with a support email. Register a Web app and copy its full Firebase configuration into `backend/firebase.json`. Mavo uses a system-browser Google PKCE flow and exchanges the verified Google credential with Firebase; it does not embed a Google login page inside the desktop webview.

Copy `backend/firebase.example.json` to `backend/firebase.json`, then fill `apiKey` and `projectId` from the Web app configuration. No service-account JSON, Admin SDK private key, or Google password belongs in this file. Restart Mavo after changing configuration. The release bundles only these public Firebase identifiers, so end users can use the login button without project setup. Keep the publisher's API restrictions compatible with Firebase Authentication and Secure Token APIs.

The file accepts all standard Web configuration fields and a directly pasted `const firebaseConfig = { ... };` snippet. It parses configuration data and never executes JavaScript. In Authentication → Settings → Authorized domains, add `localhost` for local testing if it is absent.

Firebase can remain separate from your Google connector project. Mavo can exchange the identity-only Google access credential using the Firebase Web configuration. If Firebase requires an allowed client ID, open the Google sign-in provider in Firebase Authentication, expand the option for client IDs from external projects, and allow the existing `GOOGLE_CLIENT_ID`. You do not need to replace the working connector credentials. Advanced publishers may optionally supply a separate Desktop client using `MAVO_FIREBASE_GOOGLE_CLIENT_ID` and `MAVO_FIREBASE_GOOGLE_CLIENT_SECRET`; this is optional, not part of normal end-user setup.

Firebase login is required before opening the workspace or using its APIs. Google connector consent is separate: login alone does not authorize reading or sending mail, editing calendars, or managing tasks. The first verified sign-in binds the existing Windows workspace to that Firebase account. A different account cannot silently open it. Settings provides Logout, which stops authenticated work and clears private UI state while preserving separately stored Google connector authorization. Expired or revoked identity stops authenticated work. Google resource disconnection is separate from Firebase account identity.

Local data remains in the current Windows user's workspace. Firebase Authentication stores the account identity; this release does not upload Crew, mail, or conversations to Firestore. Hosted sync and multi-user workspace switching are future features. Developers can explicitly disable the login gate with `MAVO_REQUIRE_LOGIN=false` for isolated tests; public builds use the default required login.

Packaged Google identity sign-in uses the publisher's token-exchange endpoint when the desktop has no local OAuth credential. Configure the existing Google Desktop ID/credential on that service as described in [Google setup](google-setup.md#packaged-sign-in-configure-the-existing-publisher-service). The desktop keeps state/PKCE/nonce and signed identity checks; the publisher transiently exchanges codes/tokens without storing them. This endpoint can bootstrap a new Firebase login and therefore does not require Firebase authentication itself. It is bounded to the publisher's registered client IDs, loopback redirects and supported Google scopes, with rate/body/concurrency limits. Never embed the Google client credential in an installer.
