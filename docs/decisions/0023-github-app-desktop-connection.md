# ADR 0023: public-user GitHub App connection

Status: accepted

## Decision

Use GitHub's native device authorization flow with the publisher's public GitHub App client ID/slug. One publisher registration serves all users; no shared client secret/private key or user token is distributed. Tokens generated by device flow also refresh without a client secret. Public users authorize on GitHub instead of generating personal access tokens. Keep existing token connections as an optional advanced fallback.

Device codes remain in memory, provider polling respects pending/slow-down intervals and expires, and only the short user code reaches the UI. Authorization does not commit an account: first verify identity and accessible installations/repositories, then require an explicit repository/capability selection. Discovery is bounded to five installations/100 repository choices and saves up to ten repositories. Save rechecks current provider access and same-account identity. A cancellation, disconnect, logout, account mismatch, permission removal or shutdown fences late results and preserves previously saved access unless explicitly disconnected.

Offered capabilities are the intersection of advertised installation permissions across selected repositories. GitHub additionally enforces actual user permissions. Existing per-Crew grants, hard repository limits, read/write distinctions, Actions policies and worker budgets remain in force. Connection alone cannot activate arbitrary model actions. Available reads/writes are the existing reviewed adapters, not unrestricted GitHub access.

DPAPI stores committed expiring access and refresh tokens. Refresh is serialized, rotates credentials atomically with account-change fencing, and never retries a write. 401/403 or revoked refresh authorization stops affected work. Changing repository/capability configuration clears caches and fences running Crew. GitHub usernames/repository names remain untrusted display data.

## Consequences

GitHub's standard device flow includes entering a short code; a newly authorized user may separately need to install the app on selected repositories. This is not a custom hosted OAuth redirect flow. Webhooks and GitHub source changes remain future work. Remote app revocation is done in GitHub settings; local disconnect does not uninstall it. Real testing requires the publisher's app registration and actual user consent; synthetic authorization tests are not evidence of a real connection.
